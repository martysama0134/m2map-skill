# `server_attr` — Server-Side Attribute Map

Single binary file in the map root aggregating all sectors' gameplay attributes at server resolution. The server never reads `attr.atr`; this file is its only collision/attribute source. Generated by tools (WorldEditor / converters) from the per-sectree `attr.atr` files plus object collision.

- **Path:** `<map>/server_attr` (server-side map folder; often copied alongside client files)
- **Source:** `SECTREE_MANAGER::LoadAttribute` (`m2dev-server-src/src/game/sectree_manager.cpp:450-548`)

## Layout

```
offset 0 : int32 LE  width    — server-sector columns
offset 4 : int32 LE  height   — server-sector rows
then width*height blocks, iterated for (y = 0..height-1) for (x = 0..width-1):
    uint32 LE  size           — compressed byte count
    uint8[size]                — LZO1X stream → decompresses to exactly 65,536 bytes
                                 = 128×128 uint32 LE attribute cells, row-major
```

## Grid math

Server constants (`sectree.h:6-11`):

| Constant | Value | Meaning |
|---|---|---|
| `SECTREE_SIZE` | 6400 | Server sector edge, world units (64 m) |
| `CELL_SIZE` | 50 | Attribute cell edge, world units (0.5 m) |
| cells/sector | 128 | `SECTREE_SIZE / CELL_SIZE` |

- One **client** sectree (25,600 units) = **4×4 server sectors**.
- Header dims = `MapSize * 4`: map_a2 is 6×6 client sectrees → `24 24` ✓ (verified byte-level).
- Server cell = 50 units → **2×2 server cells per client attr cell** (client attr cell = 100 units). Converters upsample each client attr byte into a 2×2 block of DWORDs.
- Sector world origin: `sectorWorldX = BasePosition.x + x * 6400` (server keys sectors by `(BaseX/6400 + x, BaseY/6400 + y)`).
- Cell lookup: `cellX = (worldX % 6400) / 50`, value = `grid[cellY * 128 + cellX]`.

## Compression

**minilzo, LZO1X**: written with `lzo1x_1_compress`, read with `lzo1x_decompress_safe` (`lzo_manager.cpp:24,32-40`). Decompressed size **must** equal 65,536 or `LoadAttribute` bails out with an error — note `Build` ignores that failure and continues (`sectree_manager.cpp:789-790`), so the map silently runs with missing/partial attributes rather than refusing to boot. Worst-case compressed size bound: `n + (n >> 4) + 67` (`lzo_manager.cpp:42-45`).

JS: use a `lzo1x` port (e.g. `lzo-wasm`, or minilzo compiled to WASM) — plain zlib/deflate is **not** compatible.

## Flags

`sectree.h:25-31`:

| Hex | Name | Meaning |
|---|---|---|
| `0x01` | `ATTR_BLOCK` | Movement blocked |
| `0x02` | `ATTR_WATER` | Water |
| `0x04` | `ATTR_BANPK` | PK forbidden |
| `0x80` | `ATTR_OBJECT` | Collision contributed by placed objects (buildings) |

Movement checks use `ATTR_BLOCK | ATTR_OBJECT`. Bits ≥ `0x100` are the "event attribute" (`GetAttribute(x,y) >> 8`, settable by quests at runtime — normally 0 on disk). Client bit values `0x01/0x02/0x04` map 1:1; `0x80` exists only here.

Element type is DWORD on disk always; the server internally re-packs to byte/word when high bits are unused (`libgame/attribute.cpp:94-147`) — irrelevant to the file format.

## Generation recipe (client → server)

Reference implementation: `WorldEditor/DataCtrl/ServerAttrGenerator.cpp:109-160`. For each server sector `(sx, sy)`:
1. Locate client sectree `(sx >> 2, sy >> 2)` and its `attr.atr` grid.
2. The server sector covers a 64×64-cell quadrant of the client 256×256 grid: offset `((sx & 3) * 64, (sy & 3) * 64)`.
3. Copy each client attr byte **verbatim** into a DWORD and upsample to 2×2 cells → 128×128 DWORD grid. No object/`.mdatr` processing happens — the `0x80` server-collision bit is already present in the painted attr bytes (see [attr-atr.md](attr-atr.md), the `0xC0`-family paints carry it). The generator optionally masks bits ≥ `0x100` (`sanitizeWeirdFlags`), never the low byte.
4. `lzo1x` compress, prefix with `uint32` size, append.

## Validation (map_a2, 589,506 bytes)

Header `18 00 00 00 18 00 00 00` = 24×24. Block walk `off += 4 + size` chains exactly: sizes 272, 272, 417, 363, … for 576 blocks ✓.

## Pitfalls

- Iteration order is **y-major** (row by row), x inner — opposite nesting from what the folder naming (`X*1000+Y`) might suggest.
- A map without `server_attr` loads server-side with no collision at all (walk-through-everything); the file is required for production maps.
- Regenerating server_attr from the sectrees' `attr.atr` files is lossless **as long as the attr bytes are preserved in full** — the `0x80` collision bit lives in those bytes, not in a separate object pass.
